# X 网页路线发帖实践（作者书面授权并知悉风险时）

本文只在作者已书面授权、知悉 X 规则风险后选择网页路线时适用；默认仍是本地发布包或官方 API。这里的做法用来降低“看起来像批量刷屏”的概率，**不能让网页脚本变得合规，也不保证不限流、不封号**。

## 1. 官方明文（2026-10-31 检索）

- 自动化规则“Don't”清单：不得使用“non-API-based forms of automation, such as scripting the X website”，可能导致**永久封号**；不得规避速率限制；不得在一个或多个账号发布重复或实质相似的帖子；不得自动蹭热门话题。<https://help.x.com/en/rules-and-policies/x-automation>
- 平台操纵与垃圾信息政策（现归入 Authenticity policy）：禁止批量、重复、无关或主动推送的内容；禁止对同一热门话题或标签发相似或重复内容；本地化成其他语言的跨发可以。<https://archive.ph/Ga9ef>（help.x.com 原页对抓取返回 403，用的是存档）
- 发帖上限：X 限额页长期写“2,400 帖/天，并按半小时切成更小的窗口，窗口大小不公开”。多家第三方称 2026-05 起，未认证账号改为 **50 条原创/天、200 条回复/天**（源自 Engadget 2026-05-18 的报道），Premium 不受此限。限额页本身本次未能直接打开（403），**以账号实际提示为准**。<https://help.x.com/en/rules-and-policies/x-limits>、<https://opentweet.io/answers/x-daily-limits-2026>、<https://api.sorsa.io/blog/twitter-api-posting-limits>

## 2. 社区经验（未经官方确认）

- “约 50 帖/30 分钟”是个流传很广的滚动窗口数字，来源只是“REPORTED”，未经证实。<https://www.tendx.app/blog/x-twitter-limits-2026>
- 多篇分析指出，这条规则看的是**手段而非数量**：模仿人类节奏的网页脚本仍属被禁止的自动化。所以随机间隔只能降低频率类信号，改变不了定性。<https://tweetreplier.com/blog/x-api-automation-rules>
- 风控是分层的：浏览器或驱动指纹、网络（IP）、账号状态、行为序列都可能触发；改指纹不能消除 IP 或行为层的判定。验证码无法稳定、合规地绕过。<https://cloakbrowser.dev/blog/playwright-detected-as-bot>、<https://www.browserstack.com/guide/playwright-captcha>
- 协同或批量行为常见的特征：共享设备或 IP、内容雷同、时间和标签同步。<https://watsspace.com?p=246062>
- 新视频上传频率、登录态频繁变化等具体触发阈值：**未找到可靠公开数据，不确定**。

## 3. 本 Skill 的执行规则（个人判断，从保守出发）

1. **间隔做成不均匀**：两次发送之间的间隔取对数正态分布，中位数约 25 分钟（μ=ln(1500 秒)，σ≈0.5），截断在 [12 分钟, 90 分钟]。理由：人的间隔右偏、偶有长停顿；固定间隔或均匀分布都更像定时器。不追求精确“像人”，主要是避免整齐的节拍和半小时窗口内的连发。
2. **每日上限**：同一账号网页路线**每天最多 6 条视频帖**（远低于任何公开上限）；同一系列一天发不完就顺延，不压缩间隔赶进度。首日或新账号减半（3 条）。
3. **下限由账本兜底**：在私有 profile 设 `pacing.x.account_seconds: 720`（12 分钟）作为硬下限（见 [pacing](pacing.md)）。现有执行器只做固定最小间隔，不睡眠、不加抖动；抖动的实际等待由调度者（Agent 或作者）在两次 `run` 之间按第 1 条取值，并把取到的秒数写进运行笔记。`x_publish_browser.py` 和 `x_video_browser.py` 目前**没有** inter-post 间隔参数，不要自造参数。
4. **每集文案差异化**：正文开头和要点每集都要不同；标签块不要逐字复制。每帖 1–2 个标签，从系列标签池中轮换，至少一个与本集内容相关；不对热门标签批量发相似内容。
5. **环境一致**：固定使用同一个专用 Chrome 配置（已登录作者账号），固定同一出口 IP 或网络；发布期间不切代理或 VPN，不换设备，不清 Cookie，不修改指纹、不用“反检测”浏览器。
6. **只用后台页签**：两次发送之间的停顿里不抢前台、不操作 X 的其他页面，不刷时间线、不点赞、不关注（不做与本次发帖无关的自动化社交动作）。
7. **硬停止，不重试**：出现验证码或 Arkose、“确认是你本人”、账号锁定或只读、速率或“稍后再试”提示、发送按钮异常、登录跳转中的任何一种，立即停止本批，任务保持原状态或“结果未知”，不点、不解、不换号、不换 IP 重试；向作者报告截图和时间（带时区）。当天不再走网页路线，恢复时间由作者决定。
8. **读回**：每次发送后按现有流程独立读回（帖子 ID、原片字节、文案），读回通过才计入当日配额并开始计下一次间隔；结果未知先 `recover-x`，不重发。

数值（25 分钟中位数、6 条/天）是保守的个人设定，不是平台规则；作者可以改得更保守，放宽前请先确认账号没有任何限流迹象。

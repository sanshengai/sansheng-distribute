# 包内浏览器引擎

这条路线不依赖额外发布 Skill、上游源码仓或常驻 MCP 服务。浏览器依赖由本包固定安装，连接作者已登录的专用 Chrome。当前实现 **X 纯文本预填**与**微博纯文本、多图预填**，均保留完整文案、普通井号文本和链接。包内抖音视频预填也已完成真实上传、字段读回与独立续跑。X 媒体、微博视频、长文章及最终发送尚未实现，其他平台继续现役 Agent 接力。不要把预填验收扩写为多平台发布完成。

## 显式配置

新安装可以在统一引导中选用，原有配置不会自动改换执行器：

```sh
python3 '<skill-root>/setup.py' --init --platform x --browser-engine x \
  --profile '/private/directory/profile.json' \
  --browser-profile '/private/directory/dedicated-chrome-profile' \
  --browser-cdp-url 'http://127.0.0.1:9333' \
  --public-identity 'x=@actual_handle'
python3 '<skill-root>/setup.py' --profile '/private/directory/profile.json' --prepare-runtime
python3 '<skill-root>/setup.py' --profile '/private/directory/profile.json' --doctor
```

端口与 profile 均从实际专用实例核对，示例端口不代表本机当前值。初始化不启动 Chrome、不登录、不启用能力。首次试验使用绑定具体清单的 `acceptance_runs`；真实账号文本预填验收通过后，才可在该账号配置中登记 `text:prefill`。没有新增媒体或公开发送能力。

既有配置可将 X 的 execute / verify 显式指向 `${SKILL_ROOT}/scripts/browser_engine.py`，分别传同名阶段和 `--profile`。保留同一账本与账号绑定，不新建任务绕过未知结果。

## X 输入与执行

交接目标使用 `content_type=text`、`endpoint=prefill`。`document_id` 可以指向已封存的纯文本来源；不把 HTML 或 Markdown 文章隐式改成普通帖。标题、两套不同描述、素材、字幕、独立封面及未映射平台字段均在写入前拒绝。平台当前长度或权限另按私有规格及实际页面核对，不截断文字。

执行前核对实际 Chrome profile、X 编辑页来源、账号切换器中的唯一 handle 与主页入口，两处身份都须等于配置。编辑页同时可能存在主页输入框和弹窗输入框，只选择唯一可见的原生编辑弹窗。已有文字、媒体或正在处理的文件选择一律保留，不自动覆盖；落尝试记录后、实际填入前再核对一次空态，发现作者新稿即停止。

执行期间该编辑器须由分发任务独占，不支持作者同时编辑：多次浏览器查询和原生输入之间不能提供跨进程原子锁。再次判空可以发现检查期间的修改，但不能保证拦住最后一次查询后恰好发生的人工输入。不要宣称此路线具备并发编辑保护。曾实测将检查与 `execCommand('insertText')` 合为一次页面任务，X 编辑器产生重复链接和换行变化，因此未采用该方法；失败试验只保留私有证据并清理本任务文字，没有发送。

第一次填入前保存私有尝试记录和真实 Chrome target ID。即使填入后连接中断，也只读核对原窗口，不重新填稿。返回的 `browser-editor:<target-id>` 明确是 **浏览器会话身份**，不是 X 草稿 ID 或推文 ID。

独立 verify 重新连接同一实例，核对同一窗口、账号、完整文案及无新增媒体，成功才报告 `prefill_ready`，同时记录 `tracking_scope=chrome_session_only`、`platform_draft_saved=false` 和 `final_click_available=false`。这不保证关闭浏览器后仍有平台草稿。每次 `run / resume` 再次读取当前窗口；窗口丢失、文字变化或加入媒体即报无法确认，不返回陈旧成功，不补填。`status` 仅显示上次观察记录。

## 微博图文预填

统一引导显式选择 `--platform weibo --browser-engine weibo`，`--public-identity 'weibo=实际数字UID'`；其他配置与 X 示例相同。初始化不登录、不安装其他 Skill、不启用能力。按具体封存目标开放 `acceptance_runs`，不启用视频和发布。

目标使用 `content_type=text` 或 `images`、`endpoint=prefill`；图文的 `asset_ids` 顺序就是图片顺序。允许普通文本来源，拒绝长文章、视频、独立标题、两套不同描述、封面、字幕、未映射平台字段和重复图片哈希。当前 `#话题#` 为普通文案，未执行原生热门话题选择，不能声称已绑定平台话题。

写入前从原生导航个人头像链接核对实际 UID，只进入唯一微博首页发布卡片。已有文字、媒体、待处理文件均停止；填入期间编辑器须由分发任务独占。连接本机专用 Chrome，写入时激活该页以让原生界面正常渲染；不重启 Chrome、不清 Cookie。

上传读取私有只读快照，复制时和每次上传前都检查封存哈希。每张图单独等待实际上传响应，确认 `ret=true` 和真实 PID 后先持久化回执，再等该 PID 对应图片完成加载且文件输入清空。检查限定在编辑卡片内，工具栏图标、信息流图片、未完成的本地预览都不能充当上传成功；完整核对 PID、图序和素材列表。

部分上传、回执缺失或中断不继续上传。独立 verify 只核对同一 Chrome target、账号、完整文案、全部逐图回执及无新增待处理文件；失败保持未知，不重传、不用另一窗口顶替。完成仍只是 `prefill_ready`，不是平台保存的草稿或公开微博。临时会话的批量 `run / resume` 同样每次重新读回；错误存在时不会报告全部终点完成。单独 `status / batch-status` 展示上次观察，不保证此刻页面仍相同。

2026-10-25 的真实两图联调已通过统一预检查、上传、独立新连接续跑，未发送。首轮在一张图后停止的失败证据保留；只清理本轮所有权明确的图片和文字，再进行修正版本的隔离预填验收。没有删除或重置生产账本。

## 抖音视频预填

显式选择 `--platform douyin --browser-engine douyin`，并用 `--public-identity 'douyin=实际抖音号'` 绑定原生首页显示的编号；昵称不能代替。初始化仍不启用能力。首次试验使用精确 `acceptance_runs`，不自动替换已有 Agent 执行器。

当前仅接受 `video:prefill`，一个 MP4、非空标题、简介和明确的单选声明；可按精确名称选择已有合集，并选择最多五个不同的原生话题。五个是本引擎的有限支持范围，不代表平台总限制。话题名称可带前导井号，不含空白或内部井号。指定封面、字幕、合集 ID、定时及其他未映射字段在上传前拒绝，不能遗漏后报告完成。`ai_generated=true` 对应“内容由AI生成”；`false` 不自动推断“无需添加自主声明”，须明确声明事实。

写入前在同一专用会话打开临时原生首页核对实际抖音号，核对后关闭该临时页；不导出 Cookie。确认唯一空上传入口，封存快照并记录 Chrome target 后只上传一次。视频预览须就绪、时长有效、文件输入清空，且原生页面显示“重新上传”；绑定所观察到的 TOS 对象与时长，不把会过期的签名 URL、预览对象或 Chrome target 当成平台草稿/作品 ID。

简介按原生行结构读回，只排除经过核对的编辑器行尾标记；作者输入的空格、隐藏字符及换行保持原样。声明点击可见的原生 radio label；外层名称先变是实时预览，取消会撤销，不能当作保存。等待该预览更新后核对单选；若此次重绘清空单选，只再次选择同一值一次，仍失败就停止。确认关闭弹窗后再读回声明。合集匹配唯一可见的完整名称，点击所属原生选项；选中状态的名称与作品计数分别读取，不把计数并入合集名。隐藏占位、同名多个合集、已有文案或其他作者选择均停止。编辑期间需独占该窗口，与 X/微博相同，不承诺拦截最后瞬间的并发人工输入。

`tags` 逐个通过“添加话题”搜索，精确匹配唯一候选并选中。读回核对编辑器原生不可编辑话题实体、名称和顺序；普通井号文字不能替代。原生标签的包装空白与零宽占位符仅在已核对结构中解释，作者字符保持不变；每个标签自动带一个普通尾随空格，随后按交接顺序保留外链。输入前核对光标在最后一行末尾，空行原生占位符的部分 Range 克隆不误判为正文；未知结构、错位、缺失或重名候选停止，不回退成普通文字。原生编辑实体的读回不是平台已保存话题 ID 的证明。

中断时保存阶段和首次上传的会话身份，`resume` 只查询同一页，不重传或补填。只有视频、完整文案、原生话题、声明、合集全部一致才能得到临时 `prefill_ready`；最后一次本地完成记录丢失时也须完整读回，不能仅凭上传标记认定完成。临时身份仍是 `chrome_session_only`，未保存平台草稿，没有发送路径。

2026-10-25 已用本任务自建四秒素材，从空上传页通过统一 `preflight / prepare / authorize / run / resume`；视频、完整文案、两个原生话题、外链、单选声明及指定合集读回一致，没有发送。早期失败与局部修复证据另存，未重置账本；完整验收采用修正后的独立试验，不能据此给生产任务未知结果另建任务重试。封面、合集 ID、定时和公开发送尚未接入。

## 来源与证据范围

借鉴固定版宝玉 X 脚本中按平台原生编辑器定位、分离上传与发送的做法；实现为本包代码，没有复制其外部运行依赖。未采用“登录 Cookie 存在即认定账号正确”“上传超时仍继续发送”或全页媒体计数作为成功判据。固定版本与许可证见 [来源清单](sources.json)，逐项取舍见 [上游采纳记录](upstream-decisions.md)。

2026-10-25 的专用 Chrome 真实联调通过了统一入口预检查、封存文案预填和新连接只读续跑；没有发送。离线测试覆盖已有草稿、错误账号、重复执行、填入后丢失响应、窗口与文字变化、未映射字段和临时身份不能充当平台草稿。真实证据只在操作者私有任务目录，公开包不包含账号、浏览器配置或账本。

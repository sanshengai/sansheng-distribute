# 包内浏览器引擎

这条路线不依赖额外发布 Skill、上游源码仓或常驻 MCP 服务。浏览器依赖由本包固定安装，连接作者已登录的专用 Chrome。当前实现 **X 文字、多图、视频预填**与**微博纯文本、多图预填**，均保留完整文案、普通井号文本和链接。包内抖音视频预填也已完成真实上传、字段读回与独立续跑。微博视频、长文章及最终发送尚未实现，其他平台继续现役 Agent 接力。不要把预填验收扩写为多平台发布完成。

后台执行是默认行为：不调用激活窗口或标签页的接口。抖音核对账号用同一浏览器上下文中的临时后台标签，按真实 target ID 确认归属并在结束后关闭；并发出现的其他页面不能被认领或关闭。扫码、验证码等需要本人时明确提示，不在循环检查中反复抢到前台。实际后台身份核对、原生页面内点击与内容读回已验证未改变前台应用及原有可见标签；这不代表所有尚未实现的平台都已完成同样验收。

后台标签的动画帧可能暂停，不能用切前台来解除常规点击等待。共用 `click_background` 在两次位置、启用状态和实际命中检查一致后，只发送一次原生指针点击；包含 Shadow DOM 上方的遮挡检查。目标变化、禁用、遮挡或位于视口外立即停止；不强制点击，不派发 DOM 点击事件，不自动重试未知结果。调用端仍须在动作前写尝试记录，并核对动作后的原生结果。此公共输入方法的原生正反例已验证，尚未据此替换已验收引擎的全部点击路径。

媒体准备也要区分“隐藏标签”和“不获取焦点的独立窗口”。Chrome 155 上，同一四秒 MP4、相同本地解码代码，在隐藏标签的五秒等待内未取得元数据；独立窗口中正常解码，且前台应用和原有可见标签均未改变。需要这类媒体处理时可使用共用 `background_window(anchor, cdp_url=...)`：先检查实际本机 `/json/protocol` 明确支持 `Target.createTarget.focus`，再以 `newWindow=true, background=false, focus=false` 创建独立窗口。旧浏览器未证实支持时停止，不用默认创建方式降级。仅关闭本次创建的窗口；不接管其他标签。

独立窗口中 X 的四秒机械测试片已出现原始字节一致的本地视频预览；统一入口已观察到原生 INIT、APPENDMULTI、FINALIZE 与 STATUS 的云端处理成功，完成独立续跑，前台应用未改变，没有发帖。本地预览、云端素材受理、平台保存草稿与公开发布分别记录。

`background_window` 默认在退出后关闭本次窗口。需要续跑的编辑器可显式使用 `retain=True`，但必须在任何写入前将真实 target ID 存入任务尝试记录；成功或异常都保留该编辑器，后续仅核对同一目标，不重传、不认领其他窗口。保留浏览器编辑器不等于平台已保存草稿，也不能将已关闭窗口作为预填终点。

## 显式配置

新安装可以在统一引导中选用，原有配置不会自动改换执行器：

```sh
python3 '<skill-root>/setup.py' --init --platform x --browser-engine x \
  --profile '/private/directory/profile.json' \
  --browser-profile '/private/directory/dedicated-chrome-profile' \
  --browser-cdp-url 'http://127.0.0.1:9333' \
  --public-identity 'x=@actual_handle'
python3 '<skill-root>/setup.py' --profile '/private/directory/profile.json' --prepare-runtime
python3 '<skill-root>/setup.py' --profile '/private/directory/profile.json' --doctor
```

端口与 profile 均从实际专用实例核对，示例端口不代表本机当前值。初始化不启动 Chrome、不登录、不启用能力。首次试验使用绑定具体清单的 `acceptance_runs`；真实账号文本预填验收通过后，才可在该账号配置中登记 `text:prefill`。图片需另按本账号的 images:prefill 范围验收；不开放发送。

既有配置可将 X 的 execute / verify 显式指向 `${SKILL_ROOT}/scripts/browser_engine.py`，分别传同名阶段和 `--profile`。保留同一账本与账号绑定，不新建任务绕过未知结果。

## X 输入与执行

交接目标使用 `content_type=text|images`、`endpoint=prefill`。`document_id` 可以指向已封存的纯文本来源；不把 HTML 或 Markdown 文章隐式改成普通帖。标题、两套不同描述、额外素材、字幕、独立封面及未映射平台字段均在写入前拒绝。平台当前长度或权限另按私有规格及实际页面核对，不截断文字。

执行前核对实际 Chrome profile、X 编辑页来源、账号切换器中的唯一 handle 与主页入口，两处身份都须等于配置。编辑页同时可能存在主页输入框和弹窗输入框，只选择唯一可见的原生编辑弹窗。已有文字、媒体或正在处理的文件选择一律保留，不自动覆盖；落尝试记录后、实际填入前再核对一次空态，发现作者新稿即停止。

执行期间该编辑器须由分发任务独占，不支持作者同时编辑：多次浏览器查询和原生输入之间不能提供跨进程原子锁。再次判空可以发现检查期间的修改，但不能保证拦住最后一次查询后恰好发生的人工输入。不要宣称此路线具备并发编辑保护。曾实测将检查与 `execCommand('insertText')` 合为一次页面任务，X 编辑器产生重复链接和换行变化，因此未采用该方法；失败试验只保留私有证据并清理本任务文字，没有发送。

第一次填入前保存私有尝试记录和真实 Chrome target ID。即使填入后连接中断，也只读核对原窗口，不重新填稿。返回的 `browser-editor:<target-id>` 明确是 **浏览器会话身份**，不是 X 草稿 ID 或推文 ID。

独立 verify 重新连接同一实例，核对同一窗口、账号、完整文案及无新增媒体，成功才报告 `prefill_ready`，同时记录 `tracking_scope=chrome_session_only`、`platform_draft_saved=false` 和 `final_click_available=false`。这不保证关闭浏览器后仍有平台草稿。每次 `run / resume` 再次读取当前窗口；窗口丢失、文字变化或加入媒体即报无法确认，不返回陈旧成功，不补填。`status` 仅显示上次观察记录。

### X 图片

图文目标按 `asset_ids` 的顺序提供一至四张静态PNG/JPEG/WebP，正文及链接与文字路线一致。当前执行器单图至多5MiB、边长至多4096像素，这是已实现范围，不是平台总限制。GIF、视频、动画图或混入的额外素材在修改前拒绝；全部图片先复制私有快照、检查哈希及解码，再填写编辑器。不使用系统剪贴板，也不要求另装发布 Skill。

通过唯一原生文件输入一次选择全部图片。只在编辑弹窗的附件容器中核对实际blob字节、尺寸、图片顺序与来源，排除账号头像、时间线图片、视频及尚未处理的文件；不能把原生字符计数的 progressbar 当成图片上传进度。blob预览本身不是云端上传完成或平台媒体ID。此路线只登记 `local_blob_preview_only`，不保存平台草稿，也没有发送路径。

续跑核对同一Chrome target、完整文案与全部原件字节。已有预览回执时还须核对同一blob身份；首次选择已被浏览器接受、但本地回执丢失时，原件字节及顺序的独立读回可以恢复临时预填状态，不再选择文件。内容不符保持未知，不通过重新上传修复。

2026-10-25 已以两张本任务机械测试图，经统一 `preflight / prepare / authorize / run / resume` 完成原生选择、真实字节/顺序及完整文案读回，没有发帖。独立封面尚未接入。新后台标签在Chrome中有时初始外层视口为零；执行器可做一次丢弃像素的原生PNG画面渲染，使编辑器正常布局，不激活窗口或标签。仍未渲染就停止，不以前台切换兜底。

## X 原生视频预填

只接收一条 MP4 和完整文案；独立封面、字幕、平台扩展字段仍拒绝。建立独立不获取焦点的编辑窗口，在首次操作前保存账号、清单摘要与真实 target ID，保留已有编辑器。选择私有原片快照后，等待原生视频处理，再填完整文案，避免选择媒体时重置文字。

回执逐响应持久化，仅观察浏览器自身的上传请求，不自行调用 X 非公开接口。必须同时核对单一媒体 ID、分块完成、最终大小、云端处理成功和有效期限，以及本地原始 blob 的 SHA-256、大小、尺寸、时长和完整文案。登记 `native_cloud_processed_and_exact_blob`；云端媒体 ID 不冒充作品 ID，临时编辑器不冒充平台草稿。

`resume` 只读取同一 target、现有预览和已记录回执。回执缺失、已过期、媒体身份改变或文案不符都保持未完成，不重传、不补写。2026-10-25 四秒机械测试片已通过统一入口、独立连接续跑及真实只读反例；缺回执、错误媒体 ID、错误原件哈希、大小不符、过期均被拒绝，未发帖。该证据不代表所有时长、编码或账号均已验收。

## 微博图文预填

统一引导显式选择 `--platform weibo --browser-engine weibo`，`--public-identity 'weibo=实际数字UID'`；其他配置与 X 示例相同。初始化不登录、不安装其他 Skill、不启用能力。按具体封存目标开放 `acceptance_runs`，不启用视频和发布。

目标使用 `content_type=text` 或 `images`、`endpoint=prefill`；图文的 `asset_ids` 顺序就是图片顺序。允许普通文本来源，拒绝长文章、视频、独立标题、两套不同描述、封面、字幕、未映射平台字段和重复图片哈希。当前 `#话题#` 为普通文案，未执行原生热门话题选择，不能声称已绑定平台话题。

写入前从原生导航个人头像链接核对实际 UID，只进入唯一微博首页发布卡片。已有文字、媒体、待处理文件均停止；填入期间编辑器须由分发任务独占。连接本机专用 Chrome，保持后台操作，不激活该页或 Chrome；不重启 Chrome、不清 Cookie。

上传读取私有只读快照，复制时和每次上传前都检查封存哈希。每张图单独等待实际上传响应，确认 `ret=true` 和真实 PID 后先持久化回执，再等该 PID 对应图片完成加载且文件输入清空。检查限定在编辑卡片内，工具栏图标、信息流图片、未完成的本地预览都不能充当上传成功；完整核对 PID、图序和素材列表。

部分上传、回执缺失或中断不继续上传。独立 verify 只核对同一 Chrome target、账号、完整文案、全部逐图回执及无新增待处理文件；失败保持未知，不重传、不用另一窗口顶替。完成仍只是 `prefill_ready`，不是平台保存的草稿或公开微博。临时会话的批量 `run / resume` 同样每次重新读回；错误存在时不会报告全部终点完成。单独 `status / batch-status` 展示上次观察，不保证此刻页面仍相同。

微博视频底层观察与上传代码位于 `scripts/weibo_video_upload.py`，尚未作为统一执行器开放。原生前端的独立入口为 `https://weibo.com/upload/channel`；原生 `$CONFIG.uid` 与 `$CONFIG.user.idstr` 必须同时匹配绑定 UID。按钮出现后，上传 SDK 仍会延迟初始化；底层先观察第二个原生点击监听器，再通过一次后台原生点击捕获临时、未连接 DOM、单文件的 `_ef` 视频选择器。不能用页面里原有的宽泛文件框替代：真实对照中，该文件框也得到云端分块校验成功，却没有进入视频编辑稿件。

调用 `select_once` 前，未来执行器须独占并核对空编辑器、持久化真实 target 与尝试记录、监听原生响应。文件交给 Chrome 之前由回调落盘，失败不能重新选择。原件按 8 MiB 分块核对浏览器实际文件与封存 SHA-256，避免整段大视频一次读入内存。`Capture` 仅保留 INIT、分块和 CHECK 必需字段，不保存签名链接或 Cookie；回执核对媒体 ID、上传 ID、实际大小、完整且无重复/缺口的字节覆盖。其 `native_cloud_file_accepted_only` 仅证明文件受理，必须另验可见的上传完成、实际编辑字段及后续续跑，不冒充平台草稿、处理完成或公开作品。

2026-10-25 的真实两图联调已通过统一预检查、上传、独立新连接续跑，未发送。首轮在一张图后停止的失败证据保留；只清理本轮所有权明确的图片和文字，再进行修正版本的隔离预填验收。没有删除或重置生产账本。

## 抖音视频预填

显式选择 `--platform douyin --browser-engine douyin`，并用 `--public-identity 'douyin=实际抖音号'` 绑定原生首页显示的编号；昵称不能代替。初始化仍不启用能力。首次试验使用精确 `acceptance_runs`，不自动替换已有 Agent 执行器。

当前仅接受 `video:prefill`，一个 MP4、非空标题、简介和明确的单选声明；可附横竖封面、按精确名称选择已有合集，并选择最多五个不同的原生话题。五个是本引擎的有限支持范围，不代表平台总限制。话题名称可带前导井号，不含空白或内部井号。字幕、合集 ID、定时及其他未映射字段在上传前拒绝，不能遗漏后报告完成。`ai_generated=true` 对应“内容由AI生成”；`false` 不自动推断“无需添加自主声明”，须明确声明事实。

写入前在同一专用会话打开临时原生首页核对实际抖音号，核对后关闭该临时页；不导出 Cookie。确认唯一空上传入口，封存快照并记录 Chrome target 后只上传一次。视频预览须就绪、时长有效、文件输入清空，且原生页面显示“重新上传”；绑定所观察到的 TOS 对象与时长，不把会过期的签名 URL、预览对象或 Chrome target 当成平台草稿/作品 ID。

简介按原生行结构读回，只排除经过核对的编辑器行尾标记；作者输入的空格、隐藏字符及换行保持原样。声明点击可见的原生 radio label；外层名称先变是实时预览，取消会撤销，不能当作保存。等待该预览更新后核对单选；若此次重绘清空单选，只再次选择同一值一次，仍失败就停止。确认关闭弹窗后再读回声明。合集匹配唯一可见的完整名称，点击所属原生选项；选中状态的名称与作品计数分别读取，不把计数并入合集名。隐藏占位、同名多个合集、已有文案或其他作者选择均停止。编辑期间需独占该窗口，与 X/微博相同，不承诺拦截最后瞬间的并发人工输入。

`tags` 逐个通过“添加话题”搜索，精确匹配唯一候选并选中。读回核对编辑器原生不可编辑话题实体、名称和顺序；普通井号文字不能替代。原生标签的包装空白与零宽占位符仅在已核对结构中解释，作者字符保持不变；每个标签自动带一个普通尾随空格，随后按交接顺序保留外链。输入前核对光标在最后一行末尾，空行原生占位符的部分 Range 克隆不误判为正文；未知结构、错位、缺失或重名候选停止，不回退成普通文字。原生编辑实体的读回不是平台已保存话题 ID 的证明。

封面在目标 `asset_ids` 登记图片，再用 `platform_metadata.cover_assets` 分别引用，例如 `{"portrait":"portrait-image-id","landscape":"landscape-image-id"}`；也可只指定一个方向。通用 `cover_asset_id` 在此路线表示竖封面，同一目标另指定 portrait 时必须一致。横竖须不同素材，比例分别为3:4和4:3；接受PNG/JPEG/WebP，当前引擎边长至多4096、源文件不超过20MiB。这是执行器范围，不是平台总限制。额外未引用图片不能丢弃，素材列表顺序也不能让图片被当成主视频。

全部源图在任何上传前经私有快照检查、浏览器解码和比例核对。原生上传器会转换为浏览器默认JPEG，实际源图必须与该确定性转换完全一致，不能将PNG原始哈希直接与JPEG比较。两方向都指定时，在同一弹窗先竖版、直接切换横版、最后完成；单方向按实际原生提示处理。不要依赖“设置横封面获更多流量”提示每次出现，也不要把竖版完成后平台自动填入的横版当成指定素材。未指定方向可能由平台保留默认图，不计为本引擎完成的指定封面。

关闭封面编辑器后逐方向核对新封面对象、原图绑定和尺寸，记录不含签名URL的回执。当前原生保存观察到宽或高少1像素，允许该已验证差异；额外缩放或裁切停止，不声称逐像素保留原件。续跑只对比已保存的对象与尺寸，不重新上传；必要时切回“预览视频”读取原视频，此操作不改稿件也不激活浏览器前台。

上传页出现“继续编辑”或上次未发布视频提示时，先停止；原生上传输入仍可用并不表示空稿，不自动覆盖或放弃暂存。原生“暂存离开”的一次真实观察返回上传页并出现本地表单缓存，未取得云端草稿ID；“继续编辑”后缓存被消费。恢复稿必须重新核对全部字段，不能仅凭视频和封面仍在就认定完整恢复。一次测试恢复后简介与封存原文不同，原因未定位，已如实拒绝完成，不据此宣称平台必然损坏文字。本路线仍未实现自动暂存或恢复点击。

中断时保存阶段和首次上传的会话身份，`resume` 只查询同一页，不重传或补填。只有视频、所指定封面、完整文案、原生话题、声明、合集全部一致才能得到临时 `prefill_ready`；最后一次本地完成记录丢失时也须完整读回，不能仅凭上传标记认定完成。临时身份仍是 `chrome_session_only`，未保存平台草稿，没有发送路径。

2026-10-25 已用本任务自建四秒素材及两张机械图，从空上传页通过统一 `preflight / prepare / authorize / run / resume`；视频、横竖两张封面、完整文案、两个原生话题、外链、单选声明及指定合集读回一致，没有发送。两方向联动是真实统一入口证据，单方向分支另有离线覆盖及原生探索，不冒称都完成独立统一入口验收。早期失败与局部修复证据另存，未重置账本；完整验收采用修正后的独立试验，不能据此给生产任务未知结果另建任务重试。合集 ID、定时和公开发送尚未接入。

## 来源与证据范围

借鉴固定版宝玉 X 脚本中按平台原生编辑器定位、分离上传与发送的做法；实现为本包代码，没有复制其外部运行依赖。未采用“登录 Cookie 存在即认定账号正确”“上传超时仍继续发送”或全页媒体计数作为成功判据。固定版本与许可证见 [来源清单](sources.json)，逐项取舍见 [上游采纳记录](upstream-decisions.md)。

2026-10-25 的专用 Chrome 真实联调通过了统一入口预检查、封存文案预填和新连接只读续跑；没有发送。离线测试覆盖已有草稿、错误账号、重复执行、填入后丢失响应、窗口与文字变化、未映射字段和临时身份不能充当平台草稿。真实证据只在操作者私有任务目录，公开包不包含账号、浏览器配置或账本。

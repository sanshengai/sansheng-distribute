# Agent 浏览器执行接力

本接口把运行时的账号锁与当前 Agent 的执行工具连接起来，不启动独立发布 APP。优先使用宿主允许的专用平台工具或已有发布脚本；通用电脑操作按当前会话的工具规则执行。某一电脑通道失败，只能说明该通道不可用，不能据此判定所有既有发布入口都失效。若工具规则要求切换 CDP/Playwright 前由用户明确指定，就先说明具体限制并取得该选择；不能借切换技术绕过限制。始终核对专用 Chrome profile，不切作者日常浏览器。

## 配置与调用

普通浏览器平台的 execute 和 verify 都指向 `scripts/agent_adapter.py`，分别传 `execute`、`verify`；`timeout_seconds` 设为 2100，接力器默认最多等待 1800 秒。路径按本机实际安装位置配置；能力在真实账号验收前保持关闭。

1. 完成 `check / prepare / authorize`，使用实际授权，不额外要求作者逐平台点击。以宿主可续查的后台命令运行 `publish.py run ...`，保留命令 session ID；不要让一个工具调用阻塞半小时。
2. 运行时产生 `<state-dir>/requests/<key>.json`。执行 `agent_adapter.py inspect --request <该文件>` 取得当前阶段、nonce、目标、快照和媒体清单。
3. 核对专用浏览器 profile 与实际账号。按当前页面观察操作，不使用文档中的旧索引或猜测按钮。每次远端写入前重新 inspect，确保接力仍存活；超时/退出后只查已有结果，不继续点击提交。
4. execute 阶段填稿/上传/按授权提交，取得真实可恢复草稿身份或内容 ID；立即以本阶段观察记录回应 pending。不能把本地 job key 或普通首页 URL 冒充远端身份。
5. 运行时随后启动新的 verify 阶段。重新打开草稿/管理列表/内容页独立读回账号、文案、媒体、封面和终点。回执 nonce 与 execute 不同，不复用旧页面观察作成功证据。
6. 保存脱敏的实际观察记录，计算文件 SHA-256；生成响应 JSON，调用 `agent_adapter.py reply --request ... --response ...`。脚本核对当前阶段、身份、证据存在与哈希。等待原发布命令返回最终状态。

响应合同：

```json
{
  "nonce":"inspect 返回的本阶段 nonce",
  "observed_phase":"同一个本阶段 nonce",
  "evidence":[{"path":"/absolute/path/本阶段观察记录.txt","sha256":"实际文件哈希"}],
  "observation":{
    "manifest_digest":"请求中的版本指纹","target_id":"实际 target id",
    "platform":"目标平台","account":"目标账号别名",
    "state":"pending","remote_id":"平台实际身份","content_verified":false
  }
}
```

verify 按终点返回 draft_ready / prefill_ready / published；正式发布附 HTTPS 永久链接。审核中返回 pending。只有独立查询确认从未提交才可返回 not_submitted + absence_verified；网络失败、看不到列表项不等于未提交。证据校验不能证明 Agent 陈述为真，必须保留实际观察，不能把离线样例填成验收。

小红书只能预填或留草稿，最终按钮由作者操作；账号受限时不启动浏览器执行。普通平台无需为了该接力让作者手动操作。

## 各平台的操作差异

以下是待真实账号验证的工作指引，不是已经测试过的选择器或发布能力。

| 平台 | 操作重点 | 独立读回 |
|---|---|---|
| X | 普通帖与长文章使用不同入口；先看实际账号的长度/视频权限。普通文本、图片、视频使用当前 compose；长文不自动改成线程 | 打开真实状态链接或保存的文章草稿，核对正文、媒体数量、视频可播放、链接；上传进度完成不代表发出 |
| 微博 | 宝玉上游只预填，不将其退出成功视为发布；按当前界面区分普通微博、视频、文章，保留话题及链接 | 从自己内容列表重新打开对应条目，绑定真实 ID、账号、文本与媒体；审核中保留 pending |
| 抖音 | 创作者后台上传视频，等待处理；核对封面、标题/说明、话题和页面要求的声明，声明依据真实来源 | 内容管理列表独立读取对应作品与审核状态；不能把“投稿成功”直接当公开可看 |
| 微信视频号 | 使用微信视频号助手，核对视频号ID、当前短标题与描述字段、封面比例、AI/原创声明和合集 | 从内容管理重新读取实际作品ID、描述、封面、合集与审核/可见状态；分享入口提供链接才登记永久链接，不拼接猜测 |
| 腾讯视频 | 使用腾讯视频创作平台，核对登录身份、入驻权限、内容类型及分类；不是视频号 | 平台内容列表与实际 v.qq.com 内容页相互核对；视频号的 ID、链接或 SAU tencent 不能代用 |
| B 站 | 确认分区、自制/转载、标题、简介、标签、封面；字幕按平台实际支持单独上传，不能静默丢弃 | 记录实际稿件身份与审核状态；正式可见后获取永久链接并播放核对 |
| 小红书 | 账号可用才预填；检查图序、封面、标题、正文和话题，最终按钮留给作者 | 预填只能报告 prefill_ready；没有可恢复编辑身份则明确仅本地包/当前页面，不伪造 draft ID |

入口来源：X/微博见锁定的 [上游来源](sources.json)；[腾讯视频创作平台](https://cc.v.qq.com/)（2026-10-24 官方搜索结果确认入口，登录内上传链未验证）。其他平台从其官方页面当前入口进入，不在未观察页面上猜 URL/DOM。

## 公众号补媒体

公众号仍由 API execute/verify；配置 `continue` 为 `agent_adapter.py execute`。API 首次建稿读回后返回 native_media_insertion_required。调用 `publish.py advance ...` 会再次只读核验，然后在同一账号锁和已有授权内交给 Agent，结束后再走官方 API 核验。操作细节及媒体回执见 [公众号](wechat.md)。继续阶段不得新建稿、整篇重贴或更换远端 ID。

请求中的 `continuation` 带本次待办。`external_link_repair_required` 仅补 `link_work` 指定的完整网址；完成、保存、读回后再进入媒体阶段。不要把修复阶段当作任意修改正文的授权。

本机 Chrome CDP 的文件上传：Playwright `set_input_files` 可能把 CDP 连接当作远端，拒绝超过 50 MB 的文件。仅在已核实 Chrome 和文件均在本机且 profile 正确时，可用 CDP `DOM.setFileInputFiles` 向当前已观察到的文件输入节点传本机绝对路径。它不需要压缩或重新制作成片；真正远端浏览器不能使用本机路径冒充可达文件。文件选中和进度到达 100% 均不代替保存、转码、插入与读回。

视频号编辑器中，插入井号文字或空格不一定完成话题转换；逐项回读原生话题实体，尤其检查最后一个话题。发布后只读证据按阶段独立保存，原生返回的媒体校验值可与源文件比较；剪裁后的封面需另查，不能用原片哈希替代封面验收。

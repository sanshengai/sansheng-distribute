# 同视频的历史任务候选

生产端对当前视频生成封存清单后，遇到改标题、改文案、换封面等新任务时，可在分发前查询同一份私有账本：

```sh
python3 scripts/duplicate_check.py --manifest /private/manifest.json --target clip --state-dir /private/state
```

脚本先核验当前清单及素材文件，随后以只读方式查询账本中相同平台、相同本地账号标识的任务；核验历史快照的摘要、任务键和目标身份后，比较目标中视频文件的 SHA-256。结果列出命中的本地任务键、状态、上次记录时间、是否同一任务，以及命中视频数。标题变化不会隐藏同一视频的候选；不同平台或不同本地账号不互相判重。

候选状态是账本的上次记录，`submission_unknown` 和 `pending` 等要先核验原任务；`published` 只表示账本曾记录发布，仍需按场景核对原作品。`same_task` 区分重复运行同一个任务与新建相似任务；该脚本不创建任务、不授权、不发送，也不自动拦截、重新发布或确认远端状态。作者有意再次发布应结合具体作品、平台状态和既有授权判断。

快照缺失、损坏或与账本身份不一致时，`unavailable_snapshot_count` 会增加，不能因为 `candidate_count` 为零而认定没有发布过。即便快照完整，它也只覆盖所选本地账本与当前本地账号标识：更换账本、改账号别名、在平台手工发布或通过其他工具发布都可能查不到；账号别名本身不是平台 UID。空结果不能证明远端无作品，也不能解除未知状态的只读恢复要求。结果包含私有账号标识和任务键，按私有材料处理。

# 上游采纳记录

固定来源与许可见 [sources.json](sources.json)。以下是对固定源码的审查结论，不代表上游所有版本，也不代表本包已经具备或验收了对应能力。没有在本轮复制这些上游可执行代码。

## 已吸收

- 宝玉：按原生编辑器定位，区分上传、预填和提交。本包 X 文本/多图/视频、微博图文采用独立实现；新增账号绑定、逐图 PID 回执、文件摘要和只读恢复。
- SAU 微博：上传完成须观察可见的实际完成状态，不能搜索页面模板中始终存在的“上传完成”文字。
- SAU 视频号：从主页进入上传入口，等待客户端挂载表单；视频上传完成可能刷新表单，合集等字段应在完成后选择并再次读回。
- SAU 抖音：应把声明选择作为独立步骤；必需声明失败就停止，不能仅写日志后继续投稿。本包以实际原生界面独立实现候选：radio label 点击、保存后声明读回、上传后选择合集。源码中的选择器只作线索，不能替代整段真实验收。
- biliup：固定版本的本机工具负责上传传输；本包适配器另行控制授权、账号、素材快照、受理回执和独立查询。真实验收范围以[平台能力与证据](platforms.md)为准，不能扩大为全部账号和投稿类型。

## 明确不采纳

| 固定源码中观察到的做法 | 本包处理 |
| --- | --- |
| 合集不存在或选择失败后警告并继续 | 指定合集属于必需交接字段；不能静默发在合集外 |
| 作者指定封面失败后改用推荐封面 | 保留现场并报告，不替换作者选择 |
| 统一写死“二创”或“含 AI 生成内容” | 按生产端来源事实分别处理原创与 AI 声明；事实不明不能猜 |
| 移除遮挡层、隐藏控件，或用强制点击继续 | 走可见原生流程；弹窗或验证需要按其含义处理 |
| 遍历“确认、继续、仍然发布”等按钮直到成功 | 每一步绑定明确语义，不把未知弹窗当通用确认 |
| 页面离开、按钮消失、进程退出 0 就报告发布成功 | 先保存实际受理身份，再通过独立查询核对账号、内容与审核/公开状态 |
| 登录 Cookie 存在就认为账号匹配 | 使用平台原生稳定身份，与私有 profile 逐项比对 |
| 未知结果重新上传或清空账本重试 | 保留首次尝试，只查询同一身份；不能确认就保持未知 |

小红书 MCP 的直接投稿末步与本 Skill“作者最终点击”不兼容，当前只作审查来源。受限账号保持本地发布包，不通过换接口、变换节奏或伪装人工绕过限制。

### Social Publish MCP

审阅 `utils/publish_ledger.py`、`publish_worker.py`、`publish_dispatch.py`、`mcp_publish_adapters.py` 及相应账本、视频号结果测试。

- 值得吸收：`before_click` 在数据库事务中先记录未知状态与尝试时间，只有首次符合条件的任务可继续；进程恢复只重排尚无提交尝试的准备任务。测试覆盖重启后禁止第二次点击、两个执行者不能同时获得提交权。保留本包现有账本、授权与进程锁，按这些失败情形检查本包，不引入第二套 SQLite 队列。
- 值得吸收：同账号、同浏览器 profile 视为冲突资源，读回与执行分开、有界检查。其调度器的活跃集合是进程内状态；本包不能用它替换已有跨进程锁，也不随上游默认值提高并行数。
- 不采纳：`verify_tencent` 以标题/组合正文和发布时间窗口匹配卡片，出现“分享、可见权限”就可记录 `PUBLISHED`；`verify_xhs` 以截短标题和时间匹配。即使只有一个候选，也没有取得稳定作品 ID。它们只能提供候选线索，不能满足本包同一作品的独立核验。
- 测试边界：上游测试正确地区分“处理中”和“已发布”，也拒绝仅按标题匹配；但允许 `title_and_publish_time` 作为证据。不能把这些测试通过解释成已经解决作品身份问题。
- 不捆绑其服务入口、会话管理器、评论功能或依赖栈。其上传器所需的 Playwright/Patchright 版本不覆盖本包运行时锁。

### OmniPost 与 SAU 的差异

对固定快照的三个上传器做了 Python AST 方法体对照，再审阅差异分支。视频号、抖音、小红书分别有 29、11、17 个同名且方法体相同的方法；这说明存在可确认的共用实现，不能将两个项目计为两份独立可靠性证明。该对照不代表仓库完整谱系或全部代码均相同。

- 新增的 AI 声明处理提示了应单独核验的原生字段；但视频号 `set_video_label` 明确允许找不到控件时跳过，小红书 `set_ai_content_declaration` 的返回值也未在调用处作为必需条件。本包只采纳独立字段的思路，必需声明无法核对时停止。
- 视频号 `apply_collection` 直接返回，不自动选择合集；图文切换和图片上传方法仍抛 `NotImplementedError`。不能将这些接口名视为已经实现合集或图文发布。
- 视频号上传等待超时后仅警告，提交循环最多尝试 600 次，并以进入管理页判断成功；小红书发布按钮有强制点击与 JavaScript 点击兜底。均不采纳。上传超时要保留现场，任何未知提交结果只读查询，不再次点击。
- 不引入其 Web 管理台和重复的上传器。后续某个差异确需移植时，另行列明具体文件、许可、修改与行为验收。

### 小红书 MCP

沿 `mcp_handlers.go → service.go → xiaohongshu/publish_video.go → publish.go` 追到实际点击与结果返回，并审阅创作者会话、上传相关测试和输入辅助代码。

- 可参考：先建立创作者中心会话、校验本地文件、等待视频处理，并将填写与提交拆成函数。Cookie 存在只表示有会话候选，不能替代本包账号稳定身份比对；发布按钮可点也不能独立证明原片已正确入稿。
- 不直接调用其视频 MCP：请求结构没有预填终点，实际路径会最终点击；返回体只有标题、正文、文件路径和“发布完成”，没有作品 ID。`waitPublishSuccess` 以 URL 离开发布表单页为成功条件，不能证明同一作品已公开。作者最终点击的账号必须在最终点击前停下。
- 原生话题值得保留，但 `inputTag` 会选择第一个联想项；找不到联想时输入空格继续。不能保证选中作者要求的话题。本包须核对真实话题身份和完整正文，必需话题不匹配时不能静默降级为普通文字。
- `humanize` 包的随机等待、曲线鼠标和逐字输入没有提供降低平台风控的对照证据，不以此承诺“像真人”或低风险。本包按原生就绪状态等待，限制同账号写入，验证或受限时停下；不追加伪装行为。
- 不引入整套 Go/HTTP/MCP 服务或浏览器伪装依赖；受限账号不做自动化实测。未覆盖该项目全部模块、所有 PR 或其他版本。

## 复核依据

SAU 固定快照审阅范围为 `uploader/{douyin,tencent,weibo,xiaohongshu}_uploader/main.py`。其中 `tencent` 对应微信视频号，不能映射为腾讯视频。微博的类型/声明、合集和提交分支，抖音的声明/封面/合集分支，以及视频号上传后重新选择合集的顺序均已核对。源码可用于找候选定位，新增路线仍须以实际原生页面和负例验收。

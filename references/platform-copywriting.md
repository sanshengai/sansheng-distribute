# 视频标题、简介与话题

适用于已有定稿的视频分发；在封存清单之前读取。平台有不同字段和表达习惯，不把一份文案复制到所有平台，也不靠运营口诀推断推荐算法。研究基线：2026-10-24；硬限制仍以当前账号实际投稿入口为准。

## 从成片到平台文案

1. 读取本集成片或权威剧本，核对人物、事件、台词与实际收益。每集提炼一个具体场景或冲突，禁止虚构剧情、教学效果、制作方式或时长承诺。
2. 分别准备标题、描述、标签/话题、封面叙述及系列/集号。标题与封面互补；系列识别保持稳定，逐集钩子有变化。学习内容同时照顾故事吸引力和准确学习点，不写成关键词堆积。
3. 标签候选覆盖内容类别、具体场景/知识点、系列；少而相关，不凑满上限、不蹭无关热榜。标签候选不是已绑定的话题。
4. 将各平台独立文案写入对应 target，再 seal。实际界面需要改文案或字段时，先更新交接包、重封存并核对已有授权范围，不能执行中静默改稿。

## 各平台映射

| 平台 | 标题与正文 | 标签/话题与现场确认 |
| --- | --- | --- |
| B站 | 标题先给具体场景/冲突，再附系列与集号；简介交代剧情、实际价值、观看方式。内容分类与自制/转载声明按真实制作来源。 | 标题、简介、投稿标签、原生话题分开处理；标签填专用区。简介中的 `#词` 不代替投稿标签或原生话题；话题须通过选择器实际选中。 |
| 抖音 | 发布文案第一句承担具体钩子，接一句真实收益与简短集号；若当前入口另有短标题，单独填写。不能假设所有入口都有同一套标题/简介字段。 | 话题通过原生选择器确认；保留有意义的完整叙述，不只留标签。不能无差别粘贴 `composed_text` 而丢失独立字段。 |
| 腾讯视频 | 标题便于剧集查找，简介简洁说明剧情与实际价值；是否可建专辑/合集以当前账号权限为准。 | 进入腾讯视频创作平台，不套用微信视频号或企鹅号规则。若无原生话题字段，保留相关标签建议，不机械粘贴井号串或声称绑定话题。 |
| 小红书 | 独立标题和正文：一个具体使用场景与能获得的体验，正文可给少量实际例句、观看方式。避免空泛效果承诺。 | 原生话题选中后回读。受限账号只准备本地包；其他账号最后点击仍由作者完成。 |

上述是编辑建议，不承诺流量。不要把“某博主用了”当作“效果很好”的证据；参考样例应记录它展示的写法与适用场景，表现数据不可得时明确写未验证。

## 投稿时补齐的证据

记录 `observed_at`、`entry_url`、`account_scope`，以及界面字段名称、字数计数/提示、文件限制、原生标签或话题选中名称。保存在任务证据中，不新增未经实现的 profile 配置键。当前 `platform_policies` 的长度检查按 Python Unicode 码点计数；须区别于平台实际计数。旧 API、其他发布入口与网页规则分别记录，不硬套永久上限。

提交前回读实际标题、简介、标签/话题实体与封面；保存后独立重开核对。只有文字中出现井号，不能登记原生话题已选中。原生选择器没有所需候选时记录缺失，不擅自替换为无关话题。平台要求原创、AI生成或其他内容声明时，按真实制作来源填写；不确定的关键声明先查生产端证据。

B站部分词属于保留话题，直接按回车不能创建普通标签；出现该提示时，改用原生话题搜索选中同名候选，并回读标签实体。封面需等待编辑器完成保存；要求同步比例时，确认同步后仍须完成封面编辑。抖音需等待封面检测和视频上传完成，再核对竖横封面、原生话题、AI声明及合集。

合集权限不足时，按用户授权先逐集投稿；不让创建合集成为投稿的隐含前置条件。账号与合集的真实对应关系保存在用户私有配置和任务证据中，不能写入公开 Skill。

上传、提交、审核中、公开可看分别记状态。已有目标的账号、素材、封面、文案和集号一一对应；批量完成率不能掩盖单集失败或错配。

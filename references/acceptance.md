# 验收与跨 Agent 使用

## 分层验收

1. **发现**：各 Agent 新进程能列出同一 Skill，软链接解析到同一本体。旧会话可能缓存旧版本，磁盘入口存在不是实际加载证据。
2. **执行**：各 Agent 读取本体，实际通过自身命令工具运行 `publish.py --help` 和无网络的本地检查；记录工具调用、退出码与输出。模型仅口头复述命令不算通过。
3. **合同**：正反例覆盖文件版本、媒体位置、授权目标、幂等、锁、超时恢复、回执绑定、Write 交接与回导。关键闸门应通过去掉校验后的变异实验，证明反例会失败。
4. **平台**：逐平台、账号、内容类型、终点做真实草稿/预填和独立读回。公众号另验媒体对应、保存重开、播放、手机宽度布局、正式 Write 回导。公开发布与群发单独验收，草稿成功不自动放行。

Claude Code、Codex、Antigravity、Grok Build 共用中性 manifest、Python CLI 与账本；只要宿主有合规本机进程工具即可调用核心。浏览器工具名称和权限依宿主而异，见 [浏览器接力](browser-execution.md)。CLI 可执行不能证明该宿主已能上传、插媒体和读取平台结果。

核心支持 macOS/Linux Python 3.10+；`fcntl` 与文件描述符继承要求 POSIX。Windows 暂未实现兼容层。公众号API模块随包提供，还需已绑定账号的私有凭证及实际网络权限；显式旧Write模块配置继续兼容。需要编辑器时另需专用Chrome与宿主浏览器能力。

## 首次能力试验

示例配置默认 `enabled_capabilities: []`。已有明确草稿/预填试验授权时，在该次私有 profile 增加精确范围，不改全局能力开关：

```json
{
  "acceptance_runs": [{
    "manifest_digest": "check 返回的实际封存指纹",
    "target_id": "清单里的目标 ID",
    "platform": "wechat",
    "account": "明确账号别名",
    "endpoint": "draft"
  }]
}
```

全部字段必须匹配当前清单，且终点只能 draft/prefill；publish/broadcast 不能用 `acceptance_runs` 开放，受限账号也不能绕过。仍需 `authorize` 记录本次实际已有授权，不能把示例文字当批准。私有试验配置不提交 Git；验收完成后移除该项，保留账本与证据。

先 `preflight`，再 `prepare / authorize / run`。`run` 内部也执行同样预检。只读恢复不要求重新开放写入能力，原稿被清理也不阻止读回。平台通过后，仅按已验收的账号范围与终点启用能力；不能因一个账号草稿成功便启用所有账号发表。

## 首次公开投稿试验

已有用户明确授权时，可在私有 profile 使用独立 `first_publication_runs`。每项必须且只能包含：`manifest_digest`、`target_id`、`platform`、`account`、`content_type`、`endpoint`、`expires_at`、`acknowledge_publication`。前六项精确绑定本次封存清单，endpoint 为 `publish`；expires_at 为含时区的 ISO 时间，剩余有效期不得超过24小时；acknowledge_publication 必须是布尔 true。

仅支持 X、微博、抖音、B站、腾讯视频、微信视频号 `wechat_channels` 的首次公开投稿，不开放公众号群发或小红书最终点击，不支持视频号冒用腾讯视频能力。此配置仍需真实 `authorize`、账号限制检查、执行锁与独立读回；不能作为授权来源，也不自动升级其他账号或后续内容的发布能力。试验完成后移除该项，保留账本和实际远端身份；审核中保持 pending。

## 重复运行本地验证

抖音 AI 视频发送候选覆盖统一核心、源上传回执门槛、点击前持久记录、末次账号/文案/选项检查、原生受理 ID 优先保存、回执异常不重发、审核未就绪的同 ID 恢复，以及原片/编辑器消失后的独立核验。原生选项与 UID 读取已真实只读观察，发送回应与正文序列化仍待具体授权下的新投稿验收；离线测试不自动升级已验收能力。

X 普通纯文字 `text:publish` 候选的离线测试覆盖唯一点击前落盘、原生受理 ID 立即保存、点击响应丢失、无 ID 不重发、错误账号/作者/作品/可见全文拒绝、独立读回失败后同 ID 恢复及默认能力不升级。去掉尝试落盘、稳定作者校验或可见全文校验，相关反例均失败；真实 Chrome 正文提取六例另验。尚未经过真实发送验收，不将这些测试计入平台公开发布通过。

X 单 MP4 的 `video:publish` 候选另覆盖共享上传与发送、即时保存作品 ID、源文件与编辑器消失后的同 ID 读回、无回执不重传、错误视频身份/播放器/源摘要拒绝、上传回执不完整和发送前预览变化拦截。12 项离线测试通过；移除媒体身份、源摘要、最后一次就绪检查或播放器可见性检查时，相关反例均失败。旧真实作品响应只证明解析形态，不算新引擎的真实发送验收。

X 另补三项实际输入前反例：检查点写入失败应保持“输入前停止”，作者在点击命中检查期间修改文字或视频预览也应停止，保留原稿与首次尝试，恢复不重填、重传或发送。移除回调中的末次就绪检查或把检查点内存更新移到持久化之前时，对应行为反例失败。

每家新宿主可先执行下方两条命令；它们仅用于本地验证，不能证明发布成功：

```sh
python3 scripts/publish.py --help
python3 examples/offline_demo.py
```

从 Skill 根执行：

```sh
python3 -m unittest discover -s tests -q
python3 scripts/publish.py --help
```

测试夹具放扫描树之外的临时目录，自动清理；不得在 Skill 内留下包含假 SKILL.md 的测试目录。平台证据保留请求范围、远端身份、实际读回及未验证边界，不记录凭证。

### 微博详情读回基础的边界

`weibo_post.py` 的离线行为检查覆盖长文截断拒绝、链接与话题、身份和公开可见性、源哈希与图片 PID/顺序绑定，以及可见正文、图片加载和永久链接。真实只读样本覆盖两条已有长文（5 图和6图），详情、可见全文及图片 PID 对齐，均在后台临时窗口内核对，原草稿未修改。该证据未绑定本次上传原件，不计为新帖发送验收；统一微博文字/多图发送候选现已接入，默认关闭；源绑定仍须在真实发送整链验收时使用实际新上传回执验证。

微博 `text/images:publish` 的16项离线验证经过真实核心账本、账号锁、执行路由和独立详情读回，覆盖单次上传/发送、回执丢失、默认能力关闭、受理 ID 立即保存、无 ID 不重试、错误账号、公开设置、原首页草稿保留、原片与任务编辑器消失后的恢复。点击前首次记录或输入检查点写入失败、最后一刻文案改变均不点击；去掉这三道保护、公开设置检查或受理作者绑定时，对应反例失败。真实首次发送必须精确配置 `first_publication_runs` 并记录实际用户授权，不能沿用预填或 X 的单帖授权。

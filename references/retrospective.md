# 分发复盘

每次分发、恢复或发布后修改结束都执行；批量任务按逐目标结果汇总一次，未完成的目标单列续跑点。复盘不代替实际发布核验。

## 先核对事实

从平台重新打开作品及合集，核对账号、真实作品 ID、可用链接、标题与集号、描述、媒体与封面、原生话题、活动、原创及 AI 声明、合集与顺序。结果区分已提交、审核中、已公开、被拒及未知；缺证据的字段明确待验，不能补写成已通过。未知结果先查询，不能借复盘重传。

## 再沉淀经验

在任务已有私有记录中追加：

- 本次平台及终点，各目标的真实结果与未完成原因。
- 新发现的限制或失败：触发条件、原始观察、根因、有效修法和复验结果。
- 下次如何避免：修改哪个通用规则、适配器或测试；现有规则已覆盖则只引用，不再重复。
- 未验证假设及下一次验证方法；没有新增经验时写明已复核、无新增规则。

只把经验证且能跨任务复用的经验写回本 Skill 的对应 reference 或代码。不要把每一次操作失误变成永久禁令，不根据单次流量推断推荐算法。界面限制注明观察日期和入口，未来执行仍以实时界面为准。关键逻辑改动加针对性反例并验证；规则更新按版本规范同步。

## 公私分开

公开 Skill 保存通用流程、平台字段行为及脱敏验证结论；账号身份、登录资料、合集 ID 与路由、作品 ID、私有路径、截图和执行证据留在用户私有配置及任务账本。页面接口证据仅保留验收必要字段，排除 token、cookie 和带签名的媒体地址。不得自动写入全局记忆或各 Agent 原生记忆。

环境或工具故障达到项目踩坑库收录标准时，先检索，再按项目模板入库；普通文案修改与临时错误不另建故障故事。

## 完成条件

结果记录可追溯、续跑点明确、可复用经验已写回且通过对应验证，才报告本次复盘完成。Skill 更新尚未同步时明确为候选；不能只口头承诺“下次记得”。

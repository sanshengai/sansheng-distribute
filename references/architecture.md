# 分发架构与能力边界

本 Skill 接收 Write、Video 或其他生产端的已选成品；它不代替创作、排版或判断内容事实。每个目标明确平台、账号、作品、字段和约定终点。平台与账号映射、合集名称、凭据、历史账本及人工核验证据属于用户的私有环境，不随 Skill 公开。

## 一条链路，分开各层

1. **交接和封存**：生产端决定正文、素材、封面和公众号媒体位置；分发端锁定来源及摘要。平台包保留差异化标题、描述、标签、声明和作者指定字段，不能自动截断或丢弃。
2. **选择路线和预检**：优先账号可用且已验收的接口；否则在宿主授权的浏览器中执行。平台规则从已验证的私有配置和当前界面获取，不以代码里的通用猜测冒充实时规则。提前识别素材、账号、字段、权限和可选依赖问题；查询不代表已登录或有发布授权。
3. **计划与授权**：每个平台账号和作品独立作为目标；草稿、预填、公开发表和群发是不同终点。已有明确授权沿用；校验或本人操作依平台及宿主工具要求进行。
4. **执行与记账**：发布前持久标记可能产生远端写入；同一账号写入受锁保护，目标之间允许受控并行。上传、平台受理、审核及公开分开报告。结果不明只读核验，不重传。
5. **独立读回与恢复**：核对实际账号、稳定作品身份和作者指定内容；正文、封面、合集、声明中某一项不确定时，分别说明，不能用提交成功代替全部字段验收。无法建立可靠身份时保留未确认状态。
6. **交付和复盘**：从账本生成私有结果页面；其他渠道的观察单独带来源和日期，不伪造账本。创作者先看平台及逐集结果，再按需展开原因、处理建议和证据。复盘以实测为依据，不承诺防风控、效率倍数或所有账号可用。

## 竞品启发及落地范围

| 来源和优点 | 这里的处理 | 验证边界 |
| --- | --- | --- |
| 宝玉 Skills：原生编辑器与内容生产相衔接 | 交接包保留生产端字段、公众号媒体锚点和原稿身份 | 公众号真实草稿与媒体补齐有单账号证据；不代表自动群发 |
| Social Auto Upload：按平台拆分上传、封面与合集 | 平台专用工作单和分项核验；明确区分视频号和腾讯视频 | 不复用未核实的自动上传器；平台支持范围见能力表 |
| Social Publish MCP：预记未知、按账号调度 | 本地账本、账号锁、失败隔离和只读恢复 | 不以标题相似代替作品身份；各平台另行验收 |
| 小红书 MCP：媒体校验、原生话题 | 保留素材和话题要求，受限账号停止 | 用户指定由作者最终点击；随机等待不代表免风控 |
| AiToEarn：素材规格、任务状态、分平台结果 | 批量预检、平台包及系列看板；可选 ffprobe 只读检查视频尺寸、时长和大小 | 本机配置的规格不是平台官方实时标准；需要转换时由生产端生成并确认新素材，不在分发时静默修改原片 |
| Postiz：可查询字段与约束、上传后分项报告 | 提供本地规则查询；工作单要求分别核验作品及附属字段 | YouTube 官方 API 视频上传已做单账号实测；分项与异常恢复仍按实际验收记录判断，不移植 AGPL 源码 |
| Mixpost：按账号独立结果、区分限额范围 | 已有每目标结果和账号锁；记录平台实际限额提示 | 可选择由用户配置本地平台/账号最小间隔，仍需人工依据；不猜测平台限额或风控 |

各来源固定版本、被拒绝的行为和复用限制见 [上游采纳记录](upstream-decisions.md)。已实现与真实账号验收分开记录在 [平台能力与证据](platforms.md)。

## 未来扩展的验收条件

添加平台或 API 需先核对官方契约、许可、账户权限和用户授权；再完成明确的字段映射、登录身份、稳定作品 ID、独立读回、结果未知恢复和负例。YouTube 候选按原会话查询偏移并由明确续传入口继续；既有单账号视频实测不代表其他账号、字段和异常恢复都已验收。未达到上述条件时，只能提供诚实标注的交接工作单或保留待处理。

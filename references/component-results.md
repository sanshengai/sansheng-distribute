# 已有作品的分项观察

已知同一作品的远端 ID 后，可将封面、合集、声明和话题的人工观察分别记录到现有私有账本。它供 `batch-report` 展示，不连接平台、不验证观察内容、不修改发布任务的状态、授权或账号锁，也不能作为自动重发的许可。作品本身的发布状态仍以原账本和独立读回为准。

1. 先在平台原生页面核对同一账号、作品 ID、指定字段和目前呈现，记录确切来源与时间。不能只凭交接计划、页面跳转或标题相似写成一致。
2. 把观察来源、事实与未确认的原因写入私有 UTF-8 文本文件，不放 Cookie、访问令牌或其他凭据。证据文件中的文字会显示在本地报告，注意避免不需要展示的个人信息。
3. 对具体任务执行（占位值需替换，时间需带时区）：

```sh
python3 scripts/component_results.py --state-dir /private/state record \
  --key JOB_KEY --remote-id REMOTE_ID --field cover --result matched \
  --evidence-file /private/cover-observation.txt --observed-at 2026-01-01T09:00:00+08:00
```

`field` 取 `cover`、`collection`、`declaration` 或 `topics`；`result` 为 `matched`（观察到一致）、`mismatch`（观察到不一致）或 `unknown`（仍未确认）。证据不能为空且最多 500 字。远端 ID 必须与账本当前同一任务一致；较旧观察不能覆盖新观察。记录以 SQLite 事务串行追加，旧观察保留；输出不打印证据或其路径。

重新生成 `batch-report` 后，原计划与分项观察分开显示；没有观察一律显示“未核验”，即使作品状态已经是“已发布”。报告将观察标为人工记录，并展示来源及日期；这不是程序的独立平台读回，也不是实时结果。账本和报告可能含私有信息，仅保存在用户自己的环境。

系列逐集看板保持紧凑：某集存在人工标记的不一致或未确认时显示“分项待查”，提示字段；详细观察和证据在 `batch-report` 查看。不因附属字段未确认而改变该集已发布计数。
